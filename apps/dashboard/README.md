# EventWatch Dashboard

The EventWatch web dashboard, built with Angular 22 (standalone components, zoneless change
detection, Signals), Tailwind CSS 4 and Chart.js via ng2-charts.

The dashboard currently runs entirely on **deterministic mock data**. There is no backend, auth or
persistence yet.

## Scripts

| Command                | What it does                                                  |
| ---------------------- | ------------------------------------------------------------- |
| `npm start`            | Dev server at http://localhost:4200 with live reload          |
| `npm run build`        | Production build to `dist/dashboard`                          |
| `npm test`             | Unit tests once (Vitest + jsdom via `@angular/build`)         |
| `npm run test:watch`   | Unit tests in watch mode                                      |
| `npm run lint`         | ESLint (TypeScript, Angular and template accessibility rules) |
| `npm run format`       | Format everything with Prettier                               |
| `npm run format:check` | Verify formatting (used in CI)                                |
| `npm run verify`       | Format check, lint, test and build in sequence (same as CI)   |

## Architecture

```
src/app/
├── core/                  App-wide singletons, no UI
│   ├── models/            Domain types (DateRange, Kpi, TopEvent, FunnelStep, …)
│   ├── api/               AnalyticsApi service + deterministic mock data generator
│   └── state/             DashboardContext: selected project and date range (signals)
├── layout/                Application shell: sidebar, header, router outlet
├── features/              One folder per route, each lazy-loaded
│   ├── overview/          KPIs, DAU chart, funnel preview, top events
│   ├── events/  users/  funnels/  settings/    Placeholder pages
└── shared/
    ├── ui/                Presentational building blocks (icon, page header, state message)
    └── utils/             Pure helpers (number/date formatting)
```

Dependency direction: `features` and `layout` may import from `core` and `shared`. `shared` imports
nothing app-specific, and features never import from each other.

### Data flow

1. `DashboardContext` holds the selected project and date range as signals. The header writes
   them, and pages read them.
2. Pages load data with `rxResource`. Its `params` read the context signals, and its `stream` calls
   `AnalyticsApi`, which returns an `Observable`. Changing the project or range cancels the
   in-flight request and starts a new one.
3. The resource exposes `isLoading()`, `error()`, `hasValue()` and `reload()`. The page template
   maps them to the loading skeleton, the error state with a retry button, and the empty or
   content states.
4. Presentational components receive plain data through signal `input()`s and derive their view
   models with `computed()`.

### Mock API

`AnalyticsApi` (`core/api/analytics-api.ts`) has the same signatures the HTTP client will have.
When the backend exists, only its method bodies change.

`core/api/mock-data.ts` generates realistic numbers that are identical on every run:

- They are anchored to a fixed date (`MOCK_TODAY`) and generated by a seeded PRNG per project and
  calendar day. The 7-day view is therefore exactly the last 7 days of the 30-day view.
- The data includes weekday and weekend seasonality, a gentle growth trend, consistent funnel and
  top-event numbers, and a previous-period comparison for every KPI.
- Requests have about 450 ms of simulated latency, so the loading states are visible.
- **DemoShop · Production** has traffic. **DemoShop · Staging** has none, which demonstrates the
  empty state.

### Conventions

- Standalone components only, with `OnPush` change detection (enforced by lint). Use `input()`,
  `output()` and `computed()` rather than decorators and lifecycle hooks.
- Templates use the built-in control flow (`@if`, `@for`, `@let`).
- TypeScript runs in `strict` mode with `noUncheckedIndexedAccess`, and Angular `strictTemplates`
  is enabled. Extended template diagnostics are treated as errors.
- Styling uses Tailwind utilities in templates. The only global styles are in `src/styles.css`:
  the `card` and `focus-ring` utilities and theme tokens.
- Chart.js is registered with only the parts it needs, in the Overview route's providers, so it
  stays out of the initial bundle.

### Accessibility

The app has a skip link, labelled landmarks, and `aria-current` on the active navigation link. The
date-range buttons use `aria-pressed`. The mobile drawer moves focus into itself, makes the
background inert, closes on Escape, and returns focus to the menu button. Charts carry a text
summary as their accessible name. Loading and empty states use `role="status"` and errors use
`role="alert"`. The app also respects `prefers-reduced-motion`.

## Testing

Unit tests sit next to the code they cover (`*.spec.ts`) and run with Vitest in jsdom. jsdom has
no canvas, so page tests replace the chart component with a stub. Run `npm test` to execute them
once.
